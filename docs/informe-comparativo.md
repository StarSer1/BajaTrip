# Informe comparativo — Unidad 1

* ¿Qué escribieron hoy a mano o qué no escriben hoy a mano que su framework les resuelve solo?
Migramos nuestro proyecto BajaTrip de un html base con estilizado de css al framework React, Despues generamos un arreglos el cual creamos para realizar las tarjetas de experiencias las cuales son llamadas "ExperienceCard" todo eso mediante "map". Hicimos layout para evitar deplicar los encabezados y pies futuros de las vistas, ademas añadimos React Route a nuestro proyecto para poder navegar entre rutas y Vite para compilar y lanzarlo a la web.


* ¿Qué parte de su trabajo no cambia al pasar al framework, y por qué?
No cambian el contenido, la semantica, la accesibilidad ni la responsividad, todo esto depende de las necesidades del usuario y del navegador.

* Para un proyecto que otro equipo va a mantener tres años: ¿dónde conviene poner más cuidado, en el sistema de diseño o en el framework? Sustenten.
En realidad para tres años de mantenimiento por otro equipo nosotros priorizamos el sistema del diseño documentado y nuestros layouts facilitan la realización del diseño de futuras vistas, por lo que sentimos que puede sobrevivir a otro cambio tecnologico. lo que si es que el framework quizasmente neceiste de futuras actualizaciones y pruebas, pero no afectaran nuestro visual por lo que por ello tenemos un diseño bastante reutilizable con componentes sencillos y controlados.
